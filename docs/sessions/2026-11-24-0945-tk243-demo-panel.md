## Findings worth keeping

- The AWS image ships only `dist/` and no `ts-node`, so `DemoSeedRunner` cannot load `prisma/seed-demo.ts`
  there. The reseed refuses with 409 "The demo seed is not in this build." until the image carries a compiled seed.
- `deploy/aws/compose.yml` and `up.sh` pin `DEMO_CONTROLS_ENABLED=false`, so the panel has its own load
  condition (`DEMO_PANEL_PASSWORD_HASH`) and needs no compose change.
- Incident owner actions require an organization member caller, so the panel acts as a live member
  (Operator first) and audits itself with `actorId` null and role `DEMO_PANEL`.
- The legacy `DemoResetRepository.reset()` drops and re-creates a foreign key (DDL). The panel uses the new
  `wipeData()`: null `business_parameters."updatedById"`, `TRUNCATE ... RESTART IDENTITY` without
  `CASCADE`, then `DELETE FROM users`. A Postgres spec checks that the schema is unchanged.
- `audit_log` is append-only for UPDATE and DELETE only, so TRUNCATE empties it; the reset audit entry is
  written after the seed.
- BigInt money in the overview broke JSON serialization; a live run caught it, and it is now a decimal
  string with a unit test.
