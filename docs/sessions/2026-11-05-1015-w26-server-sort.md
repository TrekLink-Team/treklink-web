# 2026-11-05 W26: server sort for the six paged lists

KhoaDD's agent under D-078, branch `feat/server-sort-paged-lists` from `origin/fix/table-sort-status-actions`
(treklink-web#398, not merged into `dev` when the branch was cut). Leader ruling 16:50: the six lists the
supervisor demo clicks sort on the server now (chapter 06 §11.2).

## Done

- Spec: `scripts/specs/endpoints/_common.py` `sort_query(fields, default)` adds the `sort` and `order`
  rows; regenerated devices 06, 15, 18, incidents 01, rentals 02 and billing 08, no other diff.
- Allowlists (the columns each screen shows with a meaningful order):
  - devices 06: `assetTag`, `nodeId` (by `nodeNum`), `status`, `batteryPct`, `lastSeenAt`, `serviceDueAt`
  - devices 15: `expectedAt`, `assetTag`, `status`
  - devices 18: `reportedAt`, `code`, `assetTag`, `state`
  - incidents 01: `code`, `state`, `lastEventAt`
  - rentals 02: `code`, `status`, `quantity`, `requestedStartDate`
  - billing 08: `issuedAt`, `number`, `status`, `totalVnd`, `paidVnd`
- Backend: `common/dto/sorting.ts` (`resolveSort`, `orderByOf`, `nullsLast`); each DTO validates `sort`
  with `IsIn` on its allowlist and `order` with `IsIn(['asc','desc'])`; each repository maps the field to
  its own Prisma `orderBy` with `id` as the tiebreaker in the same direction. `order` without `sort` is
  400 `VALIDATION_FAILED`. Nullable columns sort nulls last. Default orders and totals unchanged.
  `common/pipes/app-validation.pipe.ts` holds the global ValidationPipe so specs check a query DTO the
  way a request reaches it.
- Frontend: `CollectionView` `titleSort` (the title column sorts under the noun); `shared/api/query.ts`
  `SortParams`, `sortParamsOf` (nothing sent for the default order), `collectionSortOf`; entity filters
  carry `sort` and `order`, so the TanStack Query keys hold them. The fleet keeps the sort in the address.
