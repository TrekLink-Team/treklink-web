Brief W18 (leader, due 2026-11-06), built under D-078 on `claude/exciting-brown-wxv5jk`, cut from
`feat/device-connector-ui` at `a018d6d1` so it rebases with that branch.

Firmware facts read from `treklink-firmware` `dev` at `c74ddfd` and recorded with file and line in devices
design §11.13 (the ground truth file of treklink-docs still needs them; this session cannot edit it):
- `reboot_seconds` 97, `factory_reset_config` 99, `factory_reset_device` 94 and `nodedb_reset` 100 exist and
  are handled in `AdminModule.cpp`; the client library sends the first two as `reboot()` and
  `factoryResetConfig()`.
- A factory reset leaves the region `UNSET`, and with `UNSET` the firmware drops every received LoRa packet
  (`RadioLibInterface.cpp:547-552`). No TrekLink variant sets a region preference; the hub writes the region
  read before the reset back after it.
- The handshake's own NodeInfo carries `device_metrics` once the unit has measured itself, so battery and
  voltage can be read live (§11.12 Q4 revisited as §11.13 Q10).

Server: the existing reset record (api-design 10) is the factory reset's record. It already refuses a unit
that is not `RETURNED` and one still in custody; it gains the docked `nodeNum` and the `device.reset` audit.
